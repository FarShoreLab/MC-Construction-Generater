## 算法是否可取

| 内容 | 源码依据 | 价值与限制 | 本项目取舍 |
|---|---|---|---|
| 沿等高线走路 | `PotentialFieldPathfinder.computeMoveCost` | 陡坡处给沿等高线方向折扣，惩罚顺梯度移动、陡坡及较大高度变化，可减少直接冲坡。但名为 hard grade 的项在这里仍是有限软罚分。 | 最值得小范围试验；保留现有坡度、全路宽和桥跨硬约束。 |
| 三岔接入 | `SnapBranchPlanner.bestForPoint` | 比较接入节点和投影到线段的增量长度，偏向形成三岔路口，可减少每栋建筑独立拉线。它使用二维直线投影，投影点高度为 0，不证明地形可施工。 | 借鉴候选生成；投影到已验证的真实中心线，读取既有标高，再由当前路由器验证。当前已有中心线复用，应扩展它。 |
| 多种拓扑 | `RNGPlanner`、`MSTPlanner`、`KNNPlanner`、`DelaunayPlanner` | 不同连接密度有用途，但几何邻近不等于地形施工便宜。RNG 实现是两点枚举加第三点检查，最坏 O(n³)；最大边长截断后也不能自动保证全连通。 | 当前已有 plaza、MST 和冗余边，收益不足以支持新增一整套算法选项。 |
| 地形 A* | `BasicAStarPathfinder` | 综合高度、水深、近水、稳定性和直线偏离成本；但原始搜索依据地形高度移动，宽度在后处理阶段使用。直线偏离惩罚还可能压制必要绕行。 | 当前路由器已有高度状态和全宽检查，不宜用它替换。 |
| 曲线平滑 | `PathPostProcessor.process` | 先简化、桥段拉直、局部松弛，再样条采样与栅格化；默认是 Catmull–Rom，另有 Bézier 计算模式。桥段采用线性插值。 | 有视觉价值；改变路径后必须重验全宽障碍、标高、桥跨和入口，否则可能切进建筑或跨出可施工区域。暂不直接移植。 |
| 地形采样与缓存 | `TerrainSamplingCache`、精确高度采样与批量后端 | 对长距离、未生成区块道路有价值。 | 本项目已持有高度场；只有实测证明采样是瓶颈才值得引入，不能据此推断直接加速。 |

## 对“流体算法”的澄清

本次检查到的 `PotentialFieldPathfinder` 使用优先队列、累计代价和启发式搜索，等高线/梯度参与移动成本。不能仅凭 README 的 Fluid Simulation 名称，把它理解为物理水流模拟或声称其必然优于 A*。

## 最小建议

1. 首先做等高线代价的对照实验：利用现有高度场估计局部梯度，增加顺梯度移动的非负罚分。先不复制上游的基础代价折扣，避免无意改变当前启发式与移动成本的关系。
2. 若存在大量平行重复道路，再扩展当前中心线复用：把真实中心线内部点作为支路接入候选，比较新建长度、绕行和施工量；入口及已有路面标高不变。
3. 样条平滑排在这两项之后。只接受通过当前施工审计的结果，失败保留原路。

## 实施前后的验证标准

1. 固定建筑、地形、种子和搜索预算，比较现状与仅增加等高线代价的版本 → 验证：建筑入口全连通，完整路宽合法，填挖、坡度、桥跨和连续架空不越界；记录长度、填挖量、扩展状态数与耗时。
2. 使用平地、连续山坡、山脊、河谷、窄建筑通道和高低入口 → 验证：山坡收益不能以平地乱绕、窄通道失联或跨河失败为代价。
3. 三岔接入使用一条主路加多栋侧边建筑的固定案例 → 验证：新建道路量减少，既有标高不变，支路没有断口，入口绕行保持可接受。
4. 128、256、512 地图分别重复多个固定种子 → 验证：汇总成功率、耗时中位数与较慢样本；只在形态或施工量有收益且成功率、预算可接受时采用。

失败时撤回新增软代价或接入候选，保存失败坐标、路宽、标高与预算记录；不通过放宽施工硬约束换取成功率。
