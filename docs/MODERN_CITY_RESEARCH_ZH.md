# 密集现代城市规划 Demo：研究与算法取舍

日期：2026-09-27。

结论：密集城市需要先确定道路、街区和沿街地块，再安排建筑。本次 Demo 选择分级正交街网与沿街地块划分；完整张量场、任意多边形街区和交通仿真不属于首版目标。

## 当前项目为何更像聚落

- `core-planner/src/main/java/org/mcsettlement/planner/OrganicRoadNetwork.java` 明确采用“锁定建筑→广场聚类→MST→可选冗余边”。每栋建筑另接广场，主目标是可施工连通，城市街区不是基本单元。
- `core-planner/src/main/java/org/mcsettlement/planner/ExpertSettlementPlanner.java` 的选址评分包含建筑排斥与锚点距离；`city` 模式降低展开系数，但没有建立道路围合街区、连续沿街界面和分区高度。
- `docs/TWO_STAGE_DEMO_20260926_ZH.md` 所述先选建筑、再锁定连路的工作流适合人工调整聚落。密集布局可能提前占用应保留的道路走廊。
- 已有 `parcel/PlotPlanner.java` 提供沿路选址、道路净空和朝向思路，但沿路线抽样放置独立地块不等于完整街区分割。

`docs/ROADWEAVER_EVALUATION_20260927_ZH.md` 对等高线代价和三岔接入的建议仍有价值，但这些机制改善的是路线选择，不能单独补足城市街区组织。本次不整体移植 RoadWeaver，也不将其路径搜索称为物理流体模拟。

## 本次算法取舍

1. **道路先行**：以主干路和支路构成连通、可围合的正交道路骨架；街区尺寸允许受种子影响，避免所有街区相同。
2. **街区作为规划单元**：从道路边界扣除路宽与退距后安排可建区域，避免建筑生成后再挤出道路。
3. **沿街地块与短接入**：从街区边缘向内划分建筑用地，明确临街方向；内部剩余空间可以作为庭院或开放空间。建筑数量增加不应要求逐栋执行全图道路搜索。
4. **形成密度层次**：以商业核心位置和街道层级影响建筑用途及体量，使高层成组聚集、住宅连续、外围有所降低。这里是可解释的生成规则，不代表真实城市经济或交通模型。
5. **先完成可验收 Demo**：展示道路、街区、分区与建筑体量，并允许固定种子复现。首版不实现任意曲线街网、复杂张量积分、真实人口交通模拟，也不据此声称已经通过 Minecraft 施工验收。

以上是本次研究形成的设计依据；实际实现及验证结果以 Demo 源码和验收记录为准。

## 验证标准

1. 生成固定种子城市 → 验证：道路网络单连通，出现多个可辨认的闭合街区，同参数重复生成一致。
2. 检查全部地块和建筑占地 → 验证：建筑不重叠，不侵占道路与退距，每栋有明确临街面和可达入口。
3. 检查城市整体及局部体量 → 验证：密集沿街布局与中心高度聚集清晰，开放空间有明确位置，不依赖随机散布伪装城市密度。
4. 改变种子与地图规模 → 验证：拓扑及占地约束仍成立，并记录生成耗时和建筑数量。

失败时保存参数与失败几何，修复对应的道路连接、地块切分或占地校验，不通过隐藏失败建筑、放宽碰撞规则或伪报施工成功来通过验收。
