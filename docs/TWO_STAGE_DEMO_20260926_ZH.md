# 两步聚落 Demo

本地入口：http://127.0.0.1:18771/ 。启动：`python tools/preview_server.py --port 18771`。

## 操作逻辑

1. 设置地形、建筑组合与数量，点击“生成建筑选址” → 验证：只出现建筑占地，尚无道路。修改设置后重新生成；“换一组选址”沿用已生成地形，换一组选址种子。
2. 在建筑下拉列表或地图中选择一栋，填写原点 X/Z、平台 Y 与朝向，或点击“地图点选新位置”，再点击“应用位置调整” → 验证：后端检查占地、地形与入口，其他建筑的位置不变。Y 留空会重新选择可用高度；失败保留上次有效布局并显示原因。
3. 点击“确认选址，生成道路” → 验证：道路连接全部确认建筑，保持建筑预设、原点、平台高度、朝向、入口与 45° 占地；成功后自动显示施工结果。
4. 再调整建筑或道路设置 → 验证：旧道路立即失效；未应用的位置调整会禁用第二步，应用或撤回后才能重新生成道路。地形或建筑组合改变需要重新生成选址。

地图顶栏常显原始地形、选址叠加、施工结果和俯视切换。施工结果只在第二步成功后可用。地形细节、选址高级参数、道路细节和生成指标默认收起。

点选新位置、修改坐标或改变朝向后，地图立即显示黄色待选地块，整块填充与轮廓的透明度同步呼吸；原点保持静态标记，不再使用呼吸圆圈。原选址在编辑期间变为低透明灰蓝色，撤回后恢复高亮。朝向变化立即旋转真实占地，并在入口位置显示箭头；侧栏和地图浮层同时说明建筑朝向与入口朝向。四向占地和入口由后端同一个 `BuildingShape` 生成，包含 45° 栅格和非默认入口，与最终应用一致。

可连续点选改位置，地图浮层直接提供“应用此位置”和“撤回调整”；“结束点选”或 Esc 恢复地图旋转，但保留待应用草稿。校验失败时草稿变红，成功、撤回或切换建筑后清除。系统开启减少动态效果时使用静态高亮。准确的占地预览不代表该地形位置一定可放置，仍需点击应用完成校验。

## 接口与边界

`POST /api/plan` 接收 `planningStage`：

- `sites`：独立生成或重新校验全部选址，返回 `kind=SITES`、`status=SITES_READY`。不要求道路入口，不执行全局寻路和施工。该状态不能交给施工器执行。
- `roads`：要求提供全部建筑 pins 和平台 Y；最多 64 项。建筑入口索引与 45° 栅格占地也作为硬约束保留。道路连接失败明确拒绝，不通过重选建筑解决。
- `full`：旧调用默认行为，保留原来的一次性完整规划、布局硬约束及预算。旧模式可继续用于 API 对照。

两步人工确认后的布局允许用户自主决定分散范围，仍严格检查建筑碰撞、完整占地、平台和入口。第一步自动选址继续检查原有展开范围。第二步默认总预算为 1,000,000 次寻路扩展与 8,000,000 次标高求解；显式预算优先。超预算或地形不可通行会失败，已确认选址保留。

农田、桥梁与配套小屋在完整道路/施工阶段生成。农田小屋属于附属地表设施，不改变第一步主体建筑清单。

## 归档与验证

改动前的完整版本保存在本地 `.local-archive/20260927/handoff/demo-before-two-stage-20260926-130023/source.zip`，包含当时未提交的地形、农田和吊桥扩展；归档逐文件 SHA256 已校验。该本地回退包不随当前克隆提供，运行不依赖它。

- `python tools/verify_two_stage.py`：真实 Java API 验证无道路的选址、精确连路、无效位置拒绝、10 栋编辑、自定义建筑数量、真实 45° 占地和非默认入口。
- `python tools/verify_site_orientations.py`：四向展示占地、尺寸和入口与实际应用逐项比较，覆盖 45° 占地及非默认入口；证据在 `build/verification/parcel-facing/orientation-results.json`。
- `python tools/build_offline.py --test`：核心、地形、道路及旧模式回归；新增无可用道路入口仍能选址、选址 IR 不可施工的检查。
- `build/verification/two-stage/browser-acceptance.json`：实机浏览器交互验收记录。
