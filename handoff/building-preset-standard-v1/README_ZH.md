# 建筑预设标准 preset-layout/1

这是给其他 AI 制作建筑预设的独立交接包。先读本文，再读 `PROMPT_FOR_AI_ZH.md`。示例是 19×19 的木屋、独立仓库与庭院组团；并未加入默认建筑目录。

## 文件及快速验证

- `preset-layout.schema.json`：编辑器可使用的 JSON Schema。
- `example.layout.json`：作者格式，清楚分开占地、本体、附属和庭院。
- `example.native.json`：上述示例编译后的运行时格式，可由 Java `BuildingPreset` 读取。
- `compile_building_preset.py`：无第三方依赖的 Python 3 校验、编译工具。
- `INTEGRATION_ZH.md`：当前工程接口、注册步骤及验收方式。

在本文件所在目录执行：

```sh
python compile_building_preset.py example.layout.json --output compiled.json
```

输出 `PASS example_cottage_store_court: 19x19, 3 components, 3 entrances`。JSON Schema 检查字段结构；编译器额外检查连通、占地、组件重叠、体素范围和开口净空。Minecraft 方块名称的真实存在性与所有 blockstate 的合法性仍需游戏内检查。

## 坐标与占地

| 字段 | 含义 |
| --- | --- |
| `size: [X,Y,Z]` | 外包络尺寸；作者格式 X/Z 为 3–32，Y 为 3–48 |
| `reservedMask` | Z 行、每行 X 个字符；`#` 是规划和整地预留列，`.` 保持原地形 |
| `groundSymbol` | 为全部预留列提供 y=0 初始地面；组件的 y=0 可覆盖 |
| `components` | 本体、附属和户外空间的独立体素定义 |
| `entrances` | 1–8 个组团外部候选入口，规划器选择其中一个接路 |

原点在包络西北角，+X 向东、+Z 向南、+Y 向上。数组是 `layers[y][z][x]`，不是 X/Y/Z 三维数组。y=0 为地基顶面，人物站立空间从 y=1 开始。规划器会整体旋转建筑；不需要手写四份旋转模型。

预留占地必须四连通。院子若希望纳入平整和建筑间避让，必须写成 `#`；写成 `.` 的庭院洞是保留地形，不能摆放体素。整个组团使用一个基础标高；本版没有各栋独立台地和阶梯院落功能。

48×48、64×64、96×96 已封存。本包不支持生成新的大型组团；先在 7–24 格范围制作质量好的小中型预设，确有需要再使用最大 32 格。

## 组件：本体、附属、庭院

每个组件包含：

```json
{"id":"store","role":"annex","origin":[12,1],"mask":["###","###","###"],"layers":[["ggg","ggg","ggg"]]}
```

- `role` 为 `main`（本体）、`annex`（仓库/小屋）、`courtyard`、`path` 或 `garden`。至少一个 `main`。
- `origin:[x,z]` 是组件在整块占地中的偏移。组件 mask/layers 使用局部坐标，层高从全局 y=0 开始。
- 同一组件每层尺寸必须等于它的 mask，层数不超过全局 Y。
- 所有组件 mask 互不重叠，合起来必须恰好覆盖 `reservedMask`。组件可以是非矩形。
- 所有体素必须在自己组件的 mask 内；mask 外只能为空气。未写的高层保留空气。
- `palette` 是全局共用单字符到 Minecraft 方块 ID 的字典，`.` 必须为 `minecraft:air`。

语义标签本身不会生成屋顶、门窗或仓库；外观必须真实存在于 `layers` 中。示例提供了可运行的完整层数据。

## 开口方向与道路连接

```json
"entrances": [
  {"x":10,"z":18,"facing":"SOUTH"},
  {"x":0,"z":15,"facing":"WEST"},
  {"x":18,"z":15,"facing":"EAST"}
]
```

方向 NORTH=(0,-1)、EAST=(1,0)、SOUTH=(0,1)、WEST=(-1,0)。入口点必须是预留占地中的一格，沿 facing 前进一步必须离开预留占地；脚下有地板，y=1、2 净空。

这些是整个预设与道路的接驳口。独栋房屋可以放在墙边，带院组团应放在院门。每个候选入口都应通过作者制作的可走地面连接主体门与附属门；编译器不验证室内寻路。不要把入口写在院落中央或外墙死角。

本版每个预设选择一个道路入口，不是自动把所有候选入口接入道路。入口宽度为一格、净高两格；施工会修复选中入口及其向内一格的通道。未选候选不会自动封墙或自动开洞，保持原 layers。新模型最好直接画好全部合理开口。45° 变体会重采样体素，细部可能损失；首次验收请关闭斜向建筑。

## 交付要求

1. 提供 `.layout.json` → Verify：编译器无报错。
2. 提供编译的 `.native.json` → Verify：Java validateFootprint 及四向旋转通过。
3. 单栋放入平地 → Verify：占地没有裁剪，选中入口接路，本体/附属门可进入。
4. 混合生成 → Verify：数量准确、不重叠、不落水，整地和施工未超过地图预算。
5. 提供俯视占地说明和外观图 → Verify：能看出主体、附属、院落与入口，不只有一个空盒子。

失败时先修复编译器指出的字段或尺寸；布局失败时在平地关闭斜向、仅生成一栋复测，再逐项加回条件。不要缩放模型、截断 mask 或降低断言来掩盖问题。
