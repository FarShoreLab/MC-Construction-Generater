# 实现与根因报告 · 0.4.0

## 1. 实际调用链

浏览器 `tools/preview.html` → Python `preview_server.py` → Java `SimulationApiRunner` → `SimulatedSettlementPipeline` → `TerrainBlockGenerator` / `SettlementPlanner` / `BoundedSettlementPlanner` → `OrganicRoadNetwork` → `TerrainRoadRouter` → `PavementGrades` → `PlanningIR 0.4.0` → `PlanConstruction` → 模拟世界与浏览器返回值。

Fabric 的规划建筑和地面施工仍消费同一 `PlanConstruction` 编辑程序；独立放置预设的 `AdaptiveBuildingPlacer` 也按真实占地跳过空洞。没有在浏览器重新生成道路。Fabric完整类型编译及游戏运行未验证。

## 2. 地形反复：实际原因不是“某一个seed坏了”

旧 `TerrainBlockGenerator` 用固定频率0.032和0.075的正弦/余弦相加；山地还叠加 `(x-z)*0.028` 的绝对正弦脊线。seed主要改变相位，不改变频率。整数取整、截断及坡向梯度使它未必在16/32/64格产生完全相等的瓦片，但仍有很强的二维准周期。

此次对上传基线真实生成的512山地，高度在偏移(86,86)处的重叠区Pearson相关为0.9738，在(-112,112)为0.9711。常见偏移(32,32)、(64,64)也有较强相似。不能把它误报为“每64格严格复制”。

原地表材质主要为草，低于水位改为泥土；水和泥土掩码因此继承了高度的重复盆地，并不是独立材质表或水体随机数坏了。旧植被外循环按6–9格推进X，整列树共享一个X坐标，且多个过程共享扫描顺序Random状态，因此有额外列状结构。

新方案使用 `SpatialNoise` 的64位空间哈希、五次平滑、多频值噪声和领域扭曲。地表干燥区材质采用独立salt，水仍按真实低地水位形成，树按逐格哈希优先级进行局部最小值稀疏化，树冠使用各位置独立随机种子。不增加树密度来遮住高度重复。四种地形保留各自的山脊、谷地、丘陵或台阶语义。

额外检索发现旧CLI使用 `HeightfieldMap.createSynthetic`，仍有另一套正弦叠加，已一并改成同一空间噪声原语，并增加独立回归。`SimulationViewerRunner` 中剩余sin/cos用于相机旋转，不是地形生成；旧兼容寻路类保留，但不属于当前生产调用链。

四通道诊断保存所有常见位移和257×257二维自相关。材质是类别，使用机会校正的一致率而非把材质ID当连续数值做Pearson；水和树是二值通道，报告正类Jaccard及相关。全草、全干地、全水等常量背景不算重复纹理。检查中发现11个64×64相等滑窗仅各含1个少数类像素（水1窗、树10窗）；这些孤立点巧合被单独保留统计，不作为重复瓦片，也没有隐瞒初版诊断的标记。新结果未发现含有多点结构的相等64×64瓦片。

这些是固定范围和种子的自动验证，不是对所有可能seed的数学证明。新旧世界不同，不把旧241格土方与新89格土方的差值包装成单独道路算法的改善。

## 3. 直路退化：拓扑缺失与局部代价共同导致

旧流程依次选建筑候选点，再从其入口接到任意已存在道路；已有道路成为强吸附目标。连接顺序、靠中心/靠入口的候选分布、已提交标高与全宽足迹锁定，使后续建筑更倾向共享少量长连接。A*的距离启发和较小转向代价并不能自行创造中心层级、二级冗余或环路。稀缺寻路预算又会优先得到最近可行的直连。

新流程先锁定可行建筑平台和准确预设，保留原可施工布局作为安全回退，再分簇建立 `hub/plaza`。入口与枢纽先生成有界MST骨架，然后规划 `collector` 主连接、每栋建筑的 `local` 局部接入，最后尝试 `secondary` 冗余。失败连接使用有限替代端点；整套语义重布线失败时原子回退，保留原建筑数、尺寸和已验证道路，而不是裁掉建筑或放宽碰撞。

这仍是一种有预算的启发式，并非全局联合最优。先有可行布局再重做网络避免引入庞大的新求解框架，但意味着部分seed会保留可行性网络或没有回路。

参考512场景早期缺少第7栋的瓶颈是长路启发式没有表达水体绕行，预算花在错误方向。加入8×8粗网格障碍距离引导；粗格只需存在可行单元即可开放，因此它只引导代价，不用粗格结果剪掉细通道。每次粗格出队均计入原 `pathExpanded`，另以 `heuristicExpanded` 标明其子集。入口尝试在中心强约束首次失败时及时回退，避免先消耗预算填充其他地块。

## 4. 曲线与回路不是绘图特效

枢纽连线使用稀疏弧控制点、偏离引导场代价和航向连续性。8/12方向仅为离散寻路动作；真实路径仍是全宽supercover网格与标高求解结果。无法使用引导时允许有界无引导回退，不声称所有道路均为光滑样条。

对局部A-B-A-B，路由器尝试将实际中心线重排成A-A-B-B：端点、逐步高度保持，每段仍重新检查全宽障碍、保护区、水体、切填，并再次通过完整 `PavementGrades`；失败保留原路径。最多两遍、128次局部重排。参考道路的此项指标从开发中0.0466降为最终0，未新增只在画面上存在的曲线。

冗余边仅在铺装新增长度足够且实际铺装围合数增加时接受。统计同时包括语义图环秩、唯一验证环边数和实际铺装围合；不能用三格宽道路内部的小方格环冒充聚落回路。`PlanConstruction` 校验语义节点、入口、走廊端点、环标记、足迹列和指标一致性；有伪造边、缺失铺装列、篡改环数的拒绝测试。

## 5. 多尺寸、多形状建筑

新增12个JSON模板，原10个不缩小。`footprintMask` 定义实际占地，空掩码仅为原矩形的兼容表示。显式模板校验尺寸、行列、字符、四连通、门口、非空气体素与掩码一致性；不能在中庭偷偷放方块。

`BuildingPreset` 旋转掩码和方块状态；`BuildingShape` 输出基数朝向或45°重采样后的同一权威占地。平台择高、间距和碰撞使用实际集合，`PlannedBuilding` 校验消费者没有把占地变回矩形。默认掩码没有支持“随便缩放到目标尺寸”：一个预设不合适就报告该预设未能安置。

`PresetPalette` 提供classic/mixed/compact/spacious/single。classic及未显式指定预设的原请求只使用原10个模板；新增小屋不会突然抢走旧请求的候选。新组按固定ID锁定需求，明确允许选紧凑模板不等于规划器暗中缩小建筑。API默认classic，浏览器默认mixed；原参考场景必须显式选classic才与输入条件一致。

浏览器目录绘制真实掩码与面积；地块线框沿实际边界绘制，不用凸包抹平中庭。施工视图来自执行编辑程序后的真实模拟体素。

## 6. 有界性与版本

默认候选24000、寻路180000、单路状态100000、标高松弛2000000、施工列40000、编辑500000，未因参考场景提高。拓扑尝试边上限128；模板与图节点数量有界；浏览器最大512×512，矩形各边32–512，响应32MiB，单请求90秒，并发请求返回429。

PlanningIR明确升级0.4.0，消费者同步；旧0.3 IR不静默当成新语义执行。旧计划应使用旧消费者，或重新规划。渲染、仿真、Fabric都不拥有第二套道路生成真源。
