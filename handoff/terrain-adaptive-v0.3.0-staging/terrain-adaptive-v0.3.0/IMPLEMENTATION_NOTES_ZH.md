# 实现说明与硬约束说明

## 1. 原因定位与实际调用链

输入版本的主要限制并不在 Three.js 预演。`BoundedSettlementPlanner.Layout` 的入口Y被用于候选地基、四邻接寻路和最后施工列输出；后端没有可供前端展示的多层网络。仅改变道路绘制方式、道路节点标签或建筑模型朝向不会解决它。

当前生产链路：

```text
preview.html → preview_server.py → SimulationApiRunner
  → SimulatedSettlementPipeline → SettlementPlanner.plan
    → BoundedSettlementPlanner
      → BuildingShape (候选实际栅格占地)
      → TerrainRoadRouter (x,z,y,heading,rise)
      → PavementGrades (全宽实际铺装等级及楼梯朝向)
    → PlanningIR 0.3.0 / groundColumns
  → PlanConstruction.prepare → 仿真写入

Fabric: TacticalMapScreen → PlanningIntent.toPlanRequest → 同一规划器
  → WorldConstructor → 同一 PlanConstruction.prepare → 权威服务端写入

locked preset: AiBuildingArchitect → PlannedBuilding.grid → BuildingShape.grid
```

旧 `SlopeCostAStar`、`PlotPlanner` 和测试 `baseline/` 保留以维护接口和历史对照，但不是新核心的绕行施工路径。`placeStandalonePreset` 是显式独立预设命令，不接管锁定地块的施工；新方案不会借它向深层补根。

## 2. 标高与格网约定

地图和IR中的 `targetY` 是铺装/地基方块坐标Y。完整方块表面在 `targetY+1`；下半楼梯低踏面在 `targetY+0.5`，高踏面在 `targetY+1`。楼梯 `facing` 表示高半格所在的上坡方向。建筑门的accessPoint记录门槛地基方块，不是角色脚底高度。

每栋候选只对实际占地F计算可行平台区间：

```text
low  = max(terrainY(cell) - maxCutBudget), cell ∈ F
high = min(terrainY(cell) + maxFillBudget), cell ∈ F
```

low>high直接拒绝。区间内首选夹紧后的高度中位数，最小化该候选的逐列绝对挖填；若门口接入不可行，有限枚举其余合法平台标高。**入口高度不再决定建筑高度。** 仍检查原地形坡度、每格水/障碍、完整尺寸和高度、用途、河岸距离、邻近关系、地块间距及退界。

私人接入从真实门口沿修正后的基数方向伸出。门口前两格保持平台高度；仍位于自身实际footprint内的接入格必须保持平台高度；之后通过小型DP选择0/±1高差。禁止立即反向升降造成不可能的楼梯连接；连接点必须离开完整建筑退界及道路刷宽。

## 3. 路网、宽路和台阶

8方向包括四条正交与四条45°方向。12方向使用四条正交和八条对称(2,1)/(1,2)方向。这避免「8方向再补单侧4方向」造成方向偏差，并将每步碰撞检查保持在小型有界模板内。

`RoadGeometry.stencil` 先算闭中心线段与闭单位格的supercover，再作道路方形刷子的Minkowski加宽。线恰好经过角点时，两侧接触格均计入；长斜段的中间格不允许跳过。偶数宽度采用固定负侧偏移约定，宽2不会错误铺成宽3。最终几何是保守格网刷宽，而不是恒定欧氏宽度的理想连续曲线。

A*状态包含 `(x,z,y,heading,rise)`；每次0/±1高度变化。每条候选段对完整铺装模板检查：边界、所有保护/水/建筑退界、原地形最大挖填、两端锚点的逐格高度可行区间、已提交路面高度。道路代价包含正交/短斜/长斜长度、挖填、与自然标高偏离、高差、急转和反复升降。启发式使用预计算格网距离；无需抽取连续曲面等高线也会偏好少挖填的同高及缓坡延伸。它不是精确曲线/向量场跟踪器。

仅路径抵达目标不算成功。`PavementGrades` 对整个新旧铺装并集求整格标高：

- 旧道路、接入及新中心线是固定锚点；每格都有原地形挖填区间。
- 最大下界/最小上界传播确保相邻格目标高差不超过1。
- 在可行区间中尽量靠近自然地形，而不是让后来的道路刷子覆盖先前高度。
- 优先安排私人接入的踏步方向，再检查所有实际路面边缘格的连通；保留高踏面出口，避免互相冲突的楼梯朝向。
- 每个中心线宏段必须能在自身完整刷宽范围内通过真实四邻格铺装从一端走到另一端。

失败则拒绝该候选，不能提交半条路或越界补丁。当前方向配置算法是保守有限搜索：抵达目标后的完整铺装尝试最多6次；无桥梁/立交，也不把同一平面格的两个高度当成可重叠道路。

## 4. 斜向建筑不是显示旋转

`BuildingShape` 在预设四个基数朝向基础上，按开关加入45°逆映射最近栅格采样。结果包含实际占地cells、外接尺寸、原始体素采样关系、凸包展示轮廓、实际可开门边界及朝向。

`Plot.origin2D` 明确给出网格原点；`Plot.footprint` 是相对原点的真实占地。`polygon2D` 仅用于轮廓展示，不得再假定第0和第2顶点是轴对齐包围框。间距、地基标高、水体碰撞、道路退界与建造全部读取真实掩码。

`PlannedBuilding.shape` 从锁定presetId/sourceFacing/diagonal45重建，并核对尺寸、门、完整掩码。`PlanConstruction` 只在声明的foundation列中输出体素；包围框的空角保持原地形。旋转后的原预设微小装饰可能栅格失真，门口只修整为一格宽、两格净空通道；没有自作主张缩水模板来满足尺寸限制。

## 5. 施工清单和消费者

唯一列记录 `(x,z,originalY,targetY,clearToY,kind,structure,facing)`。kind分road/access/foundation；structure分surface/stair。道路、接入、平台支持与上方清理高度只能来自这些列。

`PlanConstruction.prepare` 先验证完整方案再生成写入程序：拒绝重复列、超编辑预算、超净空范围、孤立铺装、缺失全宽角格、错误高度/楼梯方向、缺失门口连接、不匹配的预设掩码与孤立地基。施工编辑按坐标去重；最终编辑数必须符合清单推导的精确数量。

楼梯输出真实 `minecraft:cobblestone_stairs[facing=...,half=bottom,shape=straight,waterlogged=false]`，不是普通整方块或仅有stair标签。清单楼梯在去重后最后写入；Fabric适配器用固定方块状态标志避免写入期间把经过验证的直踏步改成邻接转角。**该Fabric状态标志的游戏内效果仍待实际运行验证。**

Fabric施工前保留服务端线程限制、全域重扫描、原高程一致性、不可替换方块、支撑及世界高界检查。没有增加深根、暗中平整道路或桥脚；本次没有修改密钥配置，也没有触发外部模型调用。

## 6. 有界实现和大地图

搜索沿用有限多起点、需求驱动候选与贪心提交，不引入大框架。有限算术置换由seed决定候选顺序；每个需求和路由有预算份额。可达性预筛是保守加速器；如果预筛预算耗尽，未访问区域是「未知」而不是「不可达」，避免512地图被错误裁掉。

预计算水体L1距离、最近路网距离、建筑掩码积分索引。地图扫描最多512²；前置扫描不是A*扩展，但有独立固定地图界限。路径唯一状态、开放队列、标高传播工作、施工列和编辑同时设界限。

仿真把三维枚举引用数组改为扁平byte体积，分配前限制体积。浏览器每层传三个行优先高度/材质/水面数组和有限暴露附加体素；不传所有内部实心块。Java序列化在写出stdout前完整检查32MiB，Python复核，超限不返回截断成功体。每个Java任务堆1GiB、90秒，单任务锁与429避免排队堆积。

3D渲染将地形按64×64块建网格；附加物实例化，楼梯用两个半格组成。上一方案只保留轻量config/metrics/plan；没有WebGL时显示真实栅格2D回退。2D是兼容显示，不改变后端规划/施工。

## 7. 测试调整与公平比较

原21项回归名称、请求、边界与预期状态保留。旧审计中「所有道路只许正交」「所有地块必须矩形且共用高度」是旧几何假设，改为实际footprint/全宽/等级/台阶/施工后的半格通行审计；保护、水、间距、尺寸、用途、河岸、预算及入口连通没有删除。

新增审计通过另一种线段采样与角点双格规则检查足迹，而非仅复用生产supercover返回值；对施工方块字符串解析真实楼梯朝向，不把仿真枚举stair直接视为可通行。

同数量土方对照冻结用户输入的单标高生产算法（仅改包名），与新版使用同地图、入口、seed、预算、4栋同锁定预设、每栋10×10。只在双方4/4且foundation占地同为400格时比较。总绝对土方定义为每个唯一施工列 `abs(targetY-originalY)` 的和，不是道路刷子重复累计、净挖填抵消或只统计房屋地基；也不把植被清理和方块材质替换计入挖填。

全部实测数值、硬约束结果、时间、PARTIAL反例及环境限制见 `VALIDATION_REPORT_ZH.md`。不能从某几个台阶状坡地样本推出所有复杂山地改善或运行时间保证。
