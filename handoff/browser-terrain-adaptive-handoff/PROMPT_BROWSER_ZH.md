## 当前真实状态

- Java 21 核心规划器、建筑预设、施工清单和本地交互预演已经接通。
- 地形与规划种子已经拆分；同一地形可以反复 roll 规划并比较方案。
- 当前预演支持丘陵、山地、谷地、台地，显示原始地形、规划叠加、施工结果。
- 当前核心算法仍有关键限制：`BoundedSettlementPlanner` 使用四邻接、单一入口标高的道路和建筑平台。复杂地形常通过大量挖填或返回 PARTIAL；它尚未实现真正的多标高、随坡、斜向路网。

- 本地已复现 21 项核心回归和 100 个随机不变量用例；Gradle/Fabric 全量构建受运行环境 loopback 限制，不能宣称已通过游戏内验收。

## 要完成的目标

在保留现有硬约束、确定性、保护区和统一施工清单的前提下，完成以下能力：

1. **真正的地形适应道路**
   - 道路中心线允许八方向移动，形成自然斜向脉络。
   - 路径状态包含高度；相邻中心点高差通常不超过 1 格。
   - 平路标记为 `surface`，升降段标记为 `stair`，必要时明确拒绝而不是大规模挖平。
   - 路径代价优先沿等高线和缓坡，惩罚挖填、急转弯和不必要的高差变化。
   - 对角宽路必须验证完整实际铺装足迹，不能只验证中心点，也不能在拐角留下缝隙。

2. **多标高建筑布局**
   - 每个建筑候选从自身 footprint 的可行标高区间选择平台高度，不能继承统一入口高度。
   - 门槛、私人接入路径、公共道路和施工列的 Y 必须一致。
   - 建筑允许分布在坡地不同台地；平台仍受逐格最大挖方、填方、保护区、坡度和间距约束。
   - 私人接入路径可以随坡使用台阶，并连接到最近可达公共道路。

3. **扩大地图与保持有界性能**
   - 浏览器端提供 96、128、160、192、256 尺寸选择，默认 160 或 192。
   - API 接受最大 256×256，并保留严格的候选、路径展开、编辑数量和响应体预算。
   - 大地图不要向浏览器传输所有内部实心体素；只传暴露表面或使用高度场/实例化分层数据。
   - UI 显示实际尺寸、搜索预算、耗时、道路长度、台阶数、建筑标高范围和未满足原因。

4. **保持施工一致性**
   - `PlanningIR.groundColumns` 仍是道路、接入和地基施工高度的唯一真源。
   - `PlanConstruction` 按每格 targetY 施工，台阶必须具有可验证的朝向或等价可行表示。
   - 不允许道路穿过建筑、水体或受保护格；不得静默放宽硬约束。

## 必须新增的验证

1. 斜向路径确实包含对角中心线段，完整铺装足迹无漏洞、无水体/建筑碰撞。
2. 同一方案中至少两栋建筑位于不同平台标高，门槛到道路全程可步行。
3. 有高差的路线生成台阶，连续步高不超过 1；施工后的每个道路/台阶格与 IR 一致。
4. 与单标高基线相比，代表性坡地场景的总绝对挖填量明显下降，不能通过降低建筑数量伪造改善。
5. 相同地形 seed 与规划 seed 可复现；只变规划 seed 时原始地形 hash 不变。
6. 192×192 和 256×256 场景在既定预算内结束，并报告预算耗尽状态，不出现无界搜索或巨大响应。
7. 现有 21 项核心回归继续通过；如规范变化导致断言调整，必须逐项说明原因，不能直接删除测试。
