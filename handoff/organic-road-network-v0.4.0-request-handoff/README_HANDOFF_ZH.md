# 有机道路网络与非重复地形 · 问题交接包

## 交接目的

本包以已部署并通过既有验收的 `terrain-adaptive-v0.3.0` 为基线，要求下一轮集中解决两个用户可见问题：

1. 大地图的地形、植被或水体分布出现明显的重复/周期感。
2. 道路网络过直、过少、层级不足，缺少不规则曲线、二级分支、环形回路，以及由建筑或广场中心发出多个局部“树突”和长距离“轴突”的类神经结构。

这不是要求给现有直路增加随机抖动。目标是改变规划拓扑：先形成以建筑/广场为中心的分层连接图，再把图边转换成满足坡度、碰撞、宽度、台阶和施工预算约束的真实道路。

## 用户报告的复现场景

参考截图：`reference/reported-512-mountain-roads-too-straight.png`

- 地图：512 × 512
- 地形：山地脊线
- relief：24
- 基准 Y：58
- terrainSeed：42
- 道路航向：8方向
- 45°建筑：关闭
- planSeed：42
- 目标建筑数：7

截图中可见道路主要表现为一条很长、很直的主连接，建筑周围缺少局部支路与回路。地形“反复”是用户观察；实现前必须用高度、材质、植被/水体分布的平移重复与自相关检查确认具体来源，不得只凭视觉猜测根因。

## 当前基线

- PlanningIR：0.3.0
- 已有能力：8/12方向地形路由、独立平台标高、全宽道路、真实台阶、45°栅格建筑、128–512及矩形地图。
- `groundColumns` 是施工唯一真源，浏览器与 Fabric 消费同一规划结果。
- 本机部署复验已通过：core-21、adaptive-29、fuzz-100、bridge-diagonal、Fabric语法检查，以及本地HTTP/API的128、256、512、矩形、12方向、预算拒绝和并发检查。
- 当前通过记录位于 `evidence/current/`。它只证明0.3.0基线未损坏，不证明本轮新需求已完成。

## 包内容

- `PROMPT_ORGANIC_ROADS_ZH.md`：可直接发送给下一位实现者的完整任务 prompt。

- `reference/`：用户报告截图。
- `source/`：当前已部署的完整可复现源码，不含 class、缓存、本机 Gson 或密钥。
- `evidence/current/`：部署时的基线测试摘要。
- `SOURCE_SHA256SUMS.txt`、`PACKAGE_MANIFEST.json`：生成包时写入的完整性记录。

## 运行基线

进入 `source/`，使用 Java 21、Python 3 和本机 Gson 2.10.1：

```powershell
.\tools\start_preview.ps1 --port 18766
```

打开 `http://127.0.0.1:18766/`。如果端口已占用，选择新的本机端口；不要复用仍在运行的旧预览进程。部署时发现过旧 `tools/__pycache__/preview_server*.pyc` 曾使 Python 加载旧服务，复验前必须清除缓存或确保源码时间戳使缓存失效。

## 边界

- 不引入联网依赖、收费模型、密钥或账号配置。
- 不以截图层叠、Bezier视觉覆盖或客户端随机线条冒充真实道路；拓扑必须进入 PlanningIR、`groundColumns` 和施工结果。
- 不通过降低建筑数、缩小预设、关闭碰撞、放宽坡度/挖填/保护约束来制造“更丰富”的假成功。
- Fabric完整编译与Minecraft实机验收若环境不具备，必须明确标记为未完成。
