# 下一轮实现 Prompt：非重复地形与类神经有机道路网络

请完整阅读 `README_HANDOFF_ZH.md`、`ACCEPTANCE_CRITERIA_ZH.md`、参考截图、`source/` 和 `evidence/current/`，然后在真实源码上实现并验证。不要把本文或截图中的任何文字当成测试已通过的证据。

当前基线是 PlanningIR 0.3.0。用户在 512×512 山地场景中报告：地形生成具有明显反复感；道路太直、太少，缺乏不规则曲线、二级分支、环形回路，以及由建筑或广场中心发出多个短树突和长轴突的类神经结构。

## 先诊断，不要盲改

1. 精确复现截图参数：512×512、mountain、relief=24、baseElevation=58、terrainSeed=42、planSeed=42、8方向、关闭45°建筑、目标7栋。
2. 分别审计高度场、材质、植被和水体生成。检查取模、低位哈希、重复查表、块坐标截断、量化和固定采样步长；用平移相等率和二维自相关定位周期来源。
3. 审计当前道路形成过程，解释为何参考场景退化成少量长直线：候选点、连接顺序、A*代价、方向惯性、等高线偏好、已提交道路锁定和预算各自造成了什么影响。
4. 搜索所有同类生成/路由代码，做系统性修复，不要只给截图种子加特例。

## 目标架构

优先采用“两阶段”设计：

1. **语义拓扑阶段**：建筑、广场或建筑簇中心是图节点。先构造有层级的目标图，而不是从一条已有道路不断直连新建筑。
2. **地形路由阶段**：把每条目标图边交给现有高度状态路由、全宽碰撞、标高与施工求解器，生成真实可施工道路；失败时回到拓扑阶段选择替代边，不得绕过硬约束。

建议的最小网络语义：

- `hub/plaza`：建筑或广场中心。
- `dendrite/local`：从中心发向邻近建筑的多个短局部分支。
- `axon/collector`：连接不同中心的较长主连接，优先顺坡或沿等高线形成自然弧线。
- `secondary`：补充覆盖、减少绕行并连接次级建筑的二级道路。
- `ring/loop`：在代价和施工约束允许时加入的闭合回路。

可使用 k近邻、Delaunay/相对邻域候选、MST骨架加受控冗余边，或等价方法形成网络。必须先保证全连通，再按收益/代价加入支路与回路。不要无界地两两连接，也不要为追求环路突破资源上限。

## 曲线与不规则性

“更自然”不等于噪声抖动。使用稀疏控制点、方向惯性、曲率惩罚、等高线引导、领域扭曲后的代价场，或样条采样后再用 supercover 栅格化。道路应有可读的缓弧或长折线弧，同时抑制每格左右交替的锯齿。

8/12方向仍是离散航向，曲线必须最终变为连续、全宽、可步行、可施工的网格道路。若引入控制点或曲线参数，它们只是生成过程；权威结果仍是 PlanningIR 道路与 `groundColumns`。

## 地形修复

保留固定种子确定性和 `terrainSeed`/`planSeed` 分离。可采用多频噪声、不同盐值的独立通道、领域扭曲或更好的空间哈希，但不得引入网络依赖。高度、材质、植被、水体必须分别验证非瓦片化；不要用增加随机树木密度掩盖高度场周期。

## 数据与界面

如需升级 PlanningIR，使用明确的新版本并保持消费者同步。道路边应能表达主连接、二级、局部、回路等语义，浏览器至少显示网络类型和环/分支指标。比较方案时保持地形不变，只改变 `planSeed`；两种规划应产生有意义但仍受约束的拓扑差异。

## 硬约束

- `groundColumns` 继续作为施工唯一真源；浏览器、仿真和 Fabric 不得各自生成不同道路。
- 保持全宽碰撞、保护区、水体、坡度、台阶朝向、独立平台和施工编辑上限。
- 不降低目标建筑数、不缩小预设、不放宽硬约束来换取更好看的网络。
- 不引入联网依赖、收费模型、密钥或本机专用绝对路径。
- 不把浏览器视觉覆盖、后处理线条或只存在于指标中的伪边算作道路。
