日期：2026-09-20。仅记录本轮实际执行；不继承上一轮已撤回的测试结论。

## 1. 环境与执行方式

实际环境为 OpenJDK 21.0.11。核心、桥接、测试基线及独立断言入口由 `javac --release 21` 编译；核心 21 项检查通过，桥接 8 项检查通过。这里的“检查”不是冒充 JUnit 引擎报告：正式 JUnit 测试未执行，项目内另外提供两个 `*JUnitTest.java` 包装入口供正常 Gradle 环境执行。

项目声明仍为 Gson 2.10.1，未更改依赖。环境没有该依赖缓存且 DNS 不可用，本轮编译和运行使用本机 `texplate.jar` 中真实的 Gson 2.8.9；其 Maven 版本元数据及 jar 哈希保存在证据包。该 jar 不随交付分发，没有自造 Gson/JUnit 实现。**因此没有验证项目声明的 Gson 2.10.1 依赖组合。**

`bash gradlew :core-planner:test :llm-bridge:test :fabric-mod:compileJava --no-daemon` 已尝试，退出 1，阻塞于下载 Gradle 8.8：`java.net.UnknownHostException: services.gradle.org`。`gradle-final.log` 为原始记录。不能把离线编译替代成“Gradle/Fabric 编译通过”。

原算法不接受用途列表、尺寸区间、显式入口和邻近关系。比较采用相同地图、seed、总数量、道路宽度及公共土方/间距配置；把相同外部需求用于结果审计，新输入中旧算法无法表示的字段 **不回填假实现**。因此这是“同一外部任务下的原算法能力对照”，不是声称两者支持完全相同的输入语义。

旧算法的 `matched_purpose_units` 只按原始地块标签做名义匹配（`landmark` 在本测试映射为 `government`）。它不是经过真实门口、尺寸和施工验证的需求满足数；报告保留其标签匹配而不伪装成达标建筑。旧版真实门口可达数为 `NA`，不是 0，也不是自动认定全部可达。

旧版违规数是审计能确认的保护区/边界、尺寸裁剪、偶数宽度超铺、地基超限、道路高差等问题数量，属于**发现的下界**，不是已验证的完整物理违规总数。分类有按地块/道路计数与按坐标计数的区别，不应用作统一质量分数。旧版挖填只计可重建的地块土方，未报告的道路施工土方不记入；新版为全部施工列，因此不得直接拿两者总量宣称节省百分比。

`tiny_search_budget` 的旧算法状态为 `BUDGET_EXCEEDED`；CSV 的 0 来自没有返回计划的空占位结果，不表示找到零违规可行解。没有常量 S+ 或跨不同需求的总分排名。

## 5. 检查覆盖与真实失败历史

每个正式场景除预期 COMPLETE/PARTIAL/INFEASIBLE 外，还走独立审计：精确预设尺寸与用途、边界/碰撞/间距、整条道路刷宽、受保护格、逐格挖填限额、门口真实方块的地板与两格净高、邻近/河岸关系、路口格点邻接、从入口执行后洪泛可达、未满足项及预算。另有标高区间为空、40 种预设朝向门道、输入拒绝、空间依赖环、JSON 往返、旧 IR 拒绝施工及重复输入几何相同检查。

首次核心测试为 18 通过、2 失败，原始日志保留。一个是真实算法问题：小候选表被对岸不可达候选占满；增加计入统一展开预算的地形可达性预筛后解决。另一个是测试期望错误：宽 1 的私人行人接入允许通过一格缝，不应把它当宽 3 公共道路失败；保留合法缝隙用例，另外加入全封闭隔断失败用例，没有把两种情况混为一谈。

一次桥接测试错误地按原始 JSON 字符串寻找 `=`，Gson HTML 转义使断言失败；改为先解析请求 JSON 再验证 prompt 内容。该历史日志也保留。最终有效日志是 `final-tests/tests.log` 与 `final-tests/bridge-tests.log`。
